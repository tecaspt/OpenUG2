## The two rules, and why they are shaped like that

Both are tables in `tools/parity_gap.py`, applied to every package; no package is hand-decided.

### USED: what counts as a reference

Two spellings, and deliberately no third. A package is referenced when `src/` carries:

- `"UI_pause.fng"` - the whole name including the suffix, matched case-insensitively, as
  `src/gui_timing.c:9`, `src/options_menu.c:86` and `src/pause_entries.c:105`
  (`"open:ui_ReplayControl.fng"`, lowercase) write it. Case-blind because the loader hashes the
  upper-cased name (`src/ugui/ugui_assets.c:ug_assets_package`) and so is the game.
- `0xAA469286` - the 32-bit hash as a hex literal, the `src/gui_dialog.c` style. `ha_hash` is
  `fng_dump.py`'s port of `src/hud_asset.c:ha_hash`, and both constants it must reproduce are in
  `src/gui_dialog.c` and match exactly: `ha_hash("UI_InGameDialog.fng")` = `0xAA469286` =
  `PKG_IN_GAME` (line 7), `ha_hash("GenericDialog_SMALL.fng")` = `0x6962C0CD` = `KEY_PKG_SMALL`
  (line 10).

**Both ends of the name are anchored, and the left anchor is worth more than it looks.** An earlier
version of the rule matched the name with no left anchor, and `Loading.fng` was reported as the one
reference in the boot-attract class off `src/fe_menu.c:111` - a line that returns
`"PC_Loading.fng"`, a different package. Nothing in `src/` has ever named `Loading.fng`; `grep -rn
'"Loading\.fng"' src/` returns nothing. The match came from `Loading` sitting inside `PC_Loading`, and
because it was the boot class's only reference it was also inside the headline count: 34, of which one
was borrowed. Anchoring the left over name characters (letters, digits, `_`) removes it and changes
nothing else - the same run before the anchor gives 34, after gives 33, and the 87-package in-scope gap
is identical both ways, so the planning number never depended on it.

The bare stem (`UI_pause` without the suffix) was tried as a third spelling and dropped for the same
kind of reason: it found no package the suffixed name does not already find - `"open:ui_ReplayControl
.fng"` at `src/pause_entries.c:105` is matched case-insensitively by the suffixed spelling - while
admitting `FEM_SCR_LOADING`, `fem_set_loading` and ordinary prose. Two wrong readings of the same
evidence are worth naming, because both were held before the numbers were checked: the stem looked
harmless because `Loading` was already matching through the missing left anchor, and dropping the stem
then looked like the fix when it changed nothing (33 before, 33 after). Only anchoring both ends moved
the count. A single-word package name - `Loading`, `Credits`, `ScreenPrintf` - is the general risk.

Two ways to get this wrong were found while building it, both silent:

- **Strip the suffix, then forbid a following ".".** This looks like the tidy way to keep
  `GenericDialog` out of `GenericDialog_SMALL`, and it matches **no quoted package name at all**,
  because every literal in `src/` carries the suffix - `"UI_pause.fng"` is followed by the "f" of
  ".fng", which the rule rejects. Measured on this repo: the USED count falls from **34 to 19**,
  silently losing `UI_pause`, `UI_PauseOptionsMain`, `UI_OptionsMain`, `UI_ReplayControl`,
  `UI_ProfileManager`, `UI_VirtualKeyboard`, `HUD_Drag`, `HUD_Drift`, `HUD_SingleRace`,
  `HUD_Short_Track` and the four garage pickers, with no error and no false positives to notice.
  The negative lookahead on the *suffixed* spelling is what does the near-miss work.
- **Classify a whole line as a comment because it contains a comment.**
  `const char *s = "X.fng"; /* note */` is the commonest shape in this tree and would be hidden.
  Comments are stripped per line instead (`code_span`), so the match lands on the code and the
  evidence is tagged `code`, while a package named *only* in prose is tagged `comment`.

Hits are printed as `path:line` with the tag, and `--used-mode code-only` counts only code hits. The
distinction is real and not cosmetic: `Demo_MiniMap_Legend.fng` is named at `src/hud_minimap.h:48`
inside a block comment describing the minimap's art, and loaded nowhere - USED in the default mode,
not USED under `code-only`. Both spellings are in the report so a reader can tell a load site from a
note about art.

The rule is deliberately name-or-hash, not "does it draw". A package named in `fe_binding.h` is
bound and may still draw nothing - `UI_ReplayControl.fng` is the case in point, and the ROADMAP still
lists replay as missing. Reference means "some code names this screen", which is the useful planning
signal; whether it renders is a parity question this tool does not claim to answer.

### CLASS: what kind of screen it is

`CLASS_RULES` is a first-match-wins table over the name, and the order carries the meaning: the
narrow families (2-player, the console age gate, online, boot, HUD, dialog) must be tested before the
broad `^ui_` sweep, or every `UI_OL*` screen lands in frontend-screen. The console age gate
(`UI_OLAgeVerif.fng`, an ESRB "Parental Notice" screen) is the ordering case its test pins: the name
says online, the flow is console-only.

`CONTENT_RULES` decides only what the name cannot. Two content facts earned their place by being
checked in the data, not guessed:

- `ScreenPrintf.fng` is 64 text nodes all reading `DEFAULT STRING`, with no language key at all. That
  is a dev text sheet, not a screen, so all-`DEFAULT STRING` outranks even a fired name rule.
  `PC_ContextHelp.fng` is one such node, and is `other` for the same reason.
- A package with no text nodes is an art or video layer, not a screen.

`$JOY_EVENT_*` and `$SMS_*` samples are runtime fills, so they are tallied as `placeholders` and kept
out of `language_keys`; the keys themselves are `fng_dump`'s resolved English captions, which is the
key the game looks up at draw time.

## What to do with this

Nothing here is a decision to implement a screen; it is the count of what retail has and `src/` does
not name. Where it feeds the ROADMAP: M6 career is the largest block (23) and its named deliverables
are all present in retail and unreferenced; M5's tuning gap is 11 screens and 9 of them sit in a
bundle no loader opens, so they will not show up in a loader-driven audit; the online and 2-player
families are 55 packages with zero references, which is a scope question (the ROADMAP has no online
row at all) rather than a work item; `UI_ReplayControl.fng` shows that a bound package is not an
implemented screen, so M10 should be judged on behaviour, not on whether the name appears.
